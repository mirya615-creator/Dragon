## Greybox_Main 才是真实对局场景（修正 Game 场景假设）
- 场景清单确认：存在 Game.unity 与 Greybox_Main.unity；GameRankResultController(VictoryBtn 手动结算面板) 只挂在 Game/MainPanel，Greybox_Main 不用它。
- Greybox_Main 结算链路(已核实)：Canvas/SafeAreaRoot/DragonBoundPortraitScreen/SettlementPanel(初始 inactive, 挂 GreyboxSettlementRewardController)。对局终结由 TwentyWavePressureRuntime 在通关时 match.TryTransition(MatchState.Victory)(Core/MatchState.cs:63,879)；GreyboxHudView.HandleMatchStateChanged 收到 Victory/Defeat → 释放暂停 → SettlementPanel.SetActive(true)(Hud 536-557)；面板激活后 GreyboxSettlementRewardController.Start 绑定 StateChanged 并立即 HandleMatchStateChanged(已是 Victory) → PrepareAsync(Victory,Natural,None,...) → 服务端 finish → ReciveBtn/DoubleBtn 领奖回 Main。PauseExit(暂停面板 Bg/PauseBtn=ExitPausedMatch) 走 GreyboxPauseExitRewardController → Defeat+PlayerSurrender。
- MatchController.IsAllowed: next=Victory/Defeat 时只要 current 非终态即允许(含 Running/BossPrompt/Paused)，故运行中 TryTransition(Victory) 合法；TwentyWavePressureRuntime.Tick 有 match.State!=Running 早退，强制胜利后不再刷怪。CurrentWave 等值在强制胜利时均可用(≥1 需等 State==Running)。
- 结论：Greybox 里"直接调 finish(成功)"推荐让内置流程驱动——debug 热键等 bootstrap.IsInitialized && State==Running 后 TryTransition(Victory)，整条 finish+领奖链路自动走；备选为不经状态机直接 GameSettlementCoordinator.PrepareAsync(Victory,Natural,None)。此前给 Game 场景的 DebugDirectFinishController 方案作废/需改场景名。

## F9 触发的 finish 服务端返回 409 Conflict 分析
- 现象：F9 已可用（脚本挂载成功），强制 Victory 后 GreyboxSettlementRewardController 调 PrepareAsync → FinishRunAsync → POST /v1/runs/{runId}/finish，服务端返回 HTTP 409，消息 "Settlement conflicts with run state"。
- 客户端代码只有 HTTP 422 会解析响应体；409 直接以 ClientServiceException 抛出，故用户只看到 message。
- 最可能原因：服务端 run 状态机不允许在 WAVE 1 直接 Victory；或该 run 服务端视角已非 active；或事件链/随机流校验认为请求与 run 状态冲突。
- 建议：查看服务端日志/rejection_code；正常通关到 20 波再结算对比；临时在客户端也解析 409 响应体以暴露 rejection_code。
