## 「新用户首胜不加星 / 后期每两局结算」根因（2026-09-12 15:47）
- **现象**：(1) 新用户第一局胜利段位没加星；(2) 后期段位好像每两局结算一次。
- **现象 1 根因**：在线模式下**客户端段位结算被整体禁用**，星数完全押在 Go 服务端 `/v1/runs/{id}/finish`。
  - 阻断点 1：`Assets\Scripts\Services\Gameplay\GoUnaryGameplayRunGateway.cs:271`（胜利）、`:397`（quit 失败）`ApplyRank = false` 硬编码。
  - 阻断点 2：`GameSettlementCoordinator.cs:95` `if (result.ApplyRank && !ledger.RankApplied)` —— Online 模式恒 false ⇒ 客户端 `RecordVictoryAsync` 永远不被调。
  - 阻断点 3：`GoServerResourceGateways.cs:464-486` `GoPlayerRankGateway.RecordVictoryAsync` 即使被调也是空壳（只 GET `/v1/rank` 返回当前快照），注释是"服务器在 /finish 时已经结算好段位"。
  - 段位数据唯一来源：Main 场景 `GET /v1/rank` 快照。
  - 服务端现状：`Docs\DragonBound\Drakeforge_Full_Config_Baseline_V2_2026-08-14.md:370-377` 段位模块标注 "FROZEN DESIGN, PENDING IMPLEMENTATION"；`QA\Drakeforge_QA_Master_Test_Matrix_V2.md:61` 也标 "Pending server rules"。所以服务端 `/finish` 大概率**没有真正加星**。
- **现象 2 根因**：客户端**不存在**任何 `% 2` / `BatchSettle` / 隔局结算逻辑（全量检索 0 命中）。主观感受源自 `RankProgressionRules.CalculateTotalAfterDefeat`：
  - L81：Recruit~Corporal（Level 1-3）**败场不掉星**；
  - L86：Dragon Marshal (Level 10) 扣 1 但不降段；
  - L90：Sergeant~General（Level 4-9）**败场扣 1 星**。
  - 玩家胜负交替 ⇒ 净 0；**连胜两局**才净 +1 ⇒ 看起来"每两局结算一次"。
  - 加剧因素：L117-119 每段 3/4/5 星、胜+1 仅 `CurrentStars++` 不播升段动画（`MainRankController.cs:44-56` 仅在 Division 变才播 800ms 预览），体感更"没事发生"。
- **本地模式为何正常**：走 `LocalServiceModule`，`LocalGameplayRunGateway.cs:464` `ApplyRank = normalResult`，`LocalPlayerRankGateway.cs:51-54` 每胜 `+1` ⇒ 加星恒生效；与在线模式行为**不一致**。

- **修复方向（按可行性）**：
  1. **优先**：服务端补 `/finish` 的 rank 增量字段（最小 `delta_stars`），Go 端 `GoRunFinishResponse` 加段位字段，客户端 `ApplyRank` 改 `= response.settlement?.apply_rank ?? false`。
  2. 短期可降级：`GoUnaryGameplayRunGateway.cs:271/397` 临时改 `ApplyRank = true`，让 `LocalPlayerRankGateway` 路径生效（**仅本地调试用**，需要走 LocalServiceModule 而非 GoUnary）。
