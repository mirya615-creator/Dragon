## V2 部署时误播“升级烟雾”分析（2026-09-22，未执行）
- 现象：单位/组件拖到地图格落地（回弹动画）瞬间，V2 会播一次轻微烟雾。
- 根因：V2 UnitCard.prefab 的 ART_LevelUpFx 当前 `m_IsActive: 1`（用户后续在 Unity 里重做该节点时被改回激活）。节点带 Animator(controller UnitLevelUp) 且 m_Sprite=0 → 卡片 Instantiate 时 Animator 自动播放默认 state 一次（controller speed 0.2 × clip 0.1167s ≈ 0.58s），正好与落地回弹同帧；播完 LoopTime=0 停在最后一帧（alpha≈67/255）→ 残留淡淡一层。
- 为何代码没兜住：DraggableUnitView.ResolveLevelUpFx 因 levelUpAnimator 已序列化赋值，**第 544-546 行提前 return**，跳过了 fallback 分支里那句 node.SetActive(false) → 从未预隐藏该节点。
- 部署流程本身没有调用 PlayLevelUpFx（事件只由 :732 压力赛调级 / :916 合成触发）。
- 修复方向：prefab 该节点改 m_IsActive:0；把初始 SetActive(false) 提到 early-return 之前（Awake/Resolve 时无条件隐藏），并检查场景内已有 override 实例。

## V2 SlectRoad 虚线间隔加大方案（2026-09-22 输出方案，未执行）
- 实测 V2 贴图 `Variants/V2/Content/Resources/UIResources/Game/game/SlectRoad.png`：**100×100 RGBA，spriteMeshType=1(Tight)**，线条条带 y=45..53（高 9px，与 V2LineH 一致），**6 段虚线，每段 15px，间隔仅 2px**（周期 17px），x 跨度 0..98。Tight 已裁掉两端空白 → 文件里 V2LineX/YBottom/W/H 常量实际走不到（只在 FullRect 时兜底）。
- 当前渲染：tile=整条 99×9 → segmentWidth=99/9*段高；**step=segmentWidth-4(SegmentOverlap)** 会把相邻 tile 的末段与首段吃掉 ~2px → 每个 tile 接缝处两段虚线粘连（节奏不均）。这是"虚线间隔看起来偏小"的第二个成因。
- 方案（推荐，纯代码）：crop 改为**单段虚线** `new Rect(textureRect.x, textureRect.y, 15, textureRect.height)`，新增 V2 专用正间隔常量（源像素，建议 6~10）+ 运行时 `segmentGap`；step=segmentWidth+gap；段数公式改 `max(1, ceil((distance-segmentWidth)/step)+1)`（旧公式 ceil((d+overlap)/step) 在正间隔下会覆盖不足）；V2 不用 SegmentOverlap。**必须给 V1 保留原分支**否则 V1 菱形虚线段数会变。
- 美术方案（备选）：6 段×15 + 间隔 6 → 贴图宽约 120px（同路径替换无需重生成注册表，Tight 自动适配），但接缝粘连仍需代码去掉 overlap。
- 缓存坑：`ApplyAuthoredPathSprite` 里 `tiledPathSprite` 的复用守卫只比 `texture`，改裁剪常量后同 session 内会拿旧平铺单元，需把裁剪尺寸纳入守卫。
- 验证：PlayMode `BootstrapPlayModeTests.cs:271-273` 断言 `DragPathSprite` 与 `UiAssets.Load<Sprite>("GameUI/SlectRoad")` AreSame，但实现里 shaft.sprite 被替换为 Sprite.Create 的平铺单元，该断言可能本就与实际不符，改后跑一遍确认。
- **具体步骤已输出（用户手动改）**：全部在 `DragArrowPreviewView.cs`。①常量区加 `V2DashSourceWidth=15 / V2DashSourceGap=8`；②加运行时字段 `segmentGap`（默认 0=V1 行为）；③ApplyAuthoredPathSprite 把变体 ternary 提为 `isV2Variant`，Tight 分支里 V2 裁成单段 `Rect(textureRect.x, y, min(15, width), height)`（V1 保持整条），用局部 `singleDashTile` 标记；④clamp 之后按 `gap源×段高/裁剪高` 换算 segmentGap（仅 singleDashTile 时>0，V2 FullRect 兜底路径也走 0）；⑤Sprite.Create 缓存守卫加裁剪宽高比较；⑥Show() 里 step/段数分叉：gap>0 时 idealStep=段宽+gap，gapCount=round((distance-段宽)/idealStep) 且 ≥1，step=max(段宽,(distance-段宽)/gapCount) 均匀分布（首段贴起点、末段贴终点），count=gapCount+1；V1 走原公式。行 116 末段回挪在 gap 模式下因 step 均匀化恰好无操作，不改。当前段高 18 → 渲染段宽 30、间隔 16。
