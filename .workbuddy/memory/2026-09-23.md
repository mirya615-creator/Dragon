## 绕脚后仰_竖向行走无反馈的根因（已分析，未改）
- 直接原因：`UpdateHitShake` 的 `var angle = -hitShakeBackward.x * maxRadians * push;` **只看后向向量的 X 分量**；竖向 lane（前进沿 ±Y）时 `hitShakeBackward ≈ (0, ±1)`，`backward.x ≈ 0` → `angle ≈ 0` → `localRotation` 与补偿位移都≈0，卡原地不动只剩血条。
- 更深的几何原因：Unity 2D UI 的 Z 旋转只能让 sprite 顶部在世界 X 方向位移，**永远不能改 Y**。水平行走时"向后仰"恰好等价于"头往左/右偏"（后向沿 X）所以有效；竖向行走时"向后仰"等价于"头往下/上偏"，Z 旋转做不到。
- 表（行走 → 后向 → 期望头偏 → Z 旋转能否产生）：右(+X)→(-1,0)→-X ✅；左(-X)→(+1,0)→+X ✅；上(+Y)→(0,-1)→-Y ❌；下(-Y)→(0,+1)→+Y ❌。
- 即使把 `hitShakeBackward.y` 加进公式也只能贡献角度，输出位移仍只在 X 轴上，救不了竖向。这是单 RectTransform 节点做"任意方向后仰"的硬限制，不是参数错。
- 用户要求先分析，未让改代码。已列 4 个修法思路：(1) 拆 head/foot 节点（治本，代价最大，要改 V1/V2 prefab，V2 Spine 难处理）；(2) 竖向 case 改整体平移（最简单，丢脚不动语义，本质是被否的整卡后退）；(3) 竖向 lane 绑定时把 sprite 转 90° 让本地 +Y 指向运动轴（治根，要资产/绑定配合）；(4) squash-and-stretch 弹性缩放（任意方向都生效、不改资产、零代码成本，但视觉是"被踩扁"而非"后仰"）。等用户选方向。

## 关键结论：旧抖动"全线路生效" vs 新后仰"仅水平段生效"（同一条路线有横段也有竖段）
- 用户追问核心：为什么旧的左右抖动全线路都行，新的后仰只在横段成立？（附截图证实：小兵无论走竖列还是横行，UI 资源与朝向**完全不变**，永远是同一张正面朝向 sprite）
- 根本差异 = **变换自由度数量**：
  - 旧 = 屏幕空间双轴位移（`anchoredPosition + (sin(p·π·6)·d·att, sin(p·π·8)·d·0.3·att)`），**2 个自由度且完全不需要知道 lane 方向** → 任何线段都必然生效。它的"全线路生效"是设计使然，不是它做对了方向对齐。
  - 新 = 方向相关的屏内旋转，**只有 1 个自由度**：绕 Z 转 θ 时顶部 (0,h/2) → (−sinθ·h/2, cosθ·h/2)，**Y 恒为 h/2，只能沿屏幕 X 移动**。水平段后向沿 ±X，正好落在这个自由度上 ✅；竖向段后向沿 ±Y，落在它够不到的轴上 ❌。
- 第二层原因：美术朝向固定不随行进方向旋转 → sprite 不携带"行进朝向"信息，角色永远面朝观众。所以竖段的"向后仰"在视觉上等价于"人往屏幕上下倒"，**平面对称群里的刚体旋转做不到**（只有绕 X 轴 3D pitch 才行，而 UI 是正交相机，绕 X 轴只会得到垂直压扁，不是倾斜）。
- 结论：即使修正符号、把 `backward.y` 也算进角度，竖段依然无解——问题在"用屏内旋转表达方向性后仰"这个选择本身，不在参数。要任意方向成立必须换算子：位移（2 自由度，脚可不动需拆节点）或压扁/拉伸（squash-stretch）。
