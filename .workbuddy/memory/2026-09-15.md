## 13:35 V2 底部导航选中态"改了不生效"根因分析（用户问，仅分析未改代码）
- **主因：运行时 onClick 被整体重建，BottomNavigationSelection 的监听被抹掉。**
  - `MainRuneUnlockController.Awake:76` → `bagButton.onClick = new Button.ButtonClickedEvent();`
  - `MainNavTabController.Awake:94` → `rankingButton.onClick = new Button.ButtonClickedEvent();`
  - 两者都靠 `[RuntimeInitializeOnLoadMethod] sceneLoaded → AddComponent → Awake` 安装；而 `BottomNavigationSelection`（`DefaultExecutionOrder(100)`）在 Awake 阶段已 AddListener 完。sceneLoaded 在 Awake/OnEnable 之后、Start 之前触发 → 后执行的重建把 Ranking/Bag 的选中监听清空。Main 只做了 AddListener 未重建，**只有 Main 能亮**。
- **回归来源**：`MainNavTabController` 旧版在 `Update()` 里**轮询** `weaponPanel/leaderPanel.activeSelf` 换 `Main/select`↔`Main/Noselect` sprite，注释明确写着"BagBtn 的 onClick 会在运行时被 MainRuneUnlockController 重建，所以用轮询而非监听"。本次重构把这层轮询删掉（改为"视觉交给版本化 UI"），等于把当年刻意避开的坑又引回来了。
- **旧逻辑在 V2 下本来也不可用**：`UiAssets.Load<Sprite>("Main/select"/"Main/Noselect")` 这两个 key 在 V2 注册表里不存在（V2 只有 `UIResources/Main/main/*` 16 个 + `prefabs/*` 26 个）→ 会 LogError + `enabled=false`。
- **V2 场景现状**（`Variants/V2/Scenes/Main.unity`）：`BottomNavigationSelection` 挂在 ButtonNavigation（fileID 776334249），6 个引用齐全；三个按钮自身 Image 均已改为同一张 `UIResources/Main/main/6.png`（原 Ranking/Bag 误引用 **V1 的 `Main/Noselect.png`**，属跨版本串用，已修）；图标在子节点 **BG**（150×150，三个同名）上，分别为 `图层 10` / `对战` / `微信图片_...722_101`；三个按钮 `m_Transition` 已 1→0（ColorTint→None）；Ranking/Bag 的 Image alpha 已烘焙为 0、Main 为 1（Configure 菜单编辑期 `ApplySelection(Main)` 写死）。
