## APK 登录页卡住：后端配置为开发机局域网 HTTP 地址分析
- **根因定位**：`Assets/Resources/Configuration/ClientServiceConfig.asset` 中 `backendMode: 1`（GoUnary）且 `apiBaseUrl: http://192.168.31.221:8081`。
- **双重复合问题**：
  1. 手机通常不在该局域网，无法访问 `192.168.31.221:8081`；
  2. Android 9+ 默认禁止明文 HTTP，当前 launcher AndroidManifest 未声明 `android:usesCleartextTraffic="true"`。
- **项目内验证工具佐证**：`Assets/Editor/ClientServiceCompositionValidation.cs` 第 15 行要求 "Development backend must remain Local"，说明开发/本地测试预期走 `BackendMode.Local`。
- **解决方案方向**：① 改 `backendMode: 0`（Local）做离线开发包；② 或保持 GoUnary 但换成手机可访问的 HTTPS 地址并开启 cleartext（仅调试）；③ 长期用多配置资产区分 Dev/Release。
- **后续**：用户提到截图中可能还有第二个 Main 初始化报错，建议先修配置再验证。

## 后端模式切换（Local vs GoUnary）影响面核查
- **架构事实**：`ClientCompositionRoot`（`BeforeSceneLoad` 的 `RuntimeInitializeOnLoadMethod`）是唯一分叉点，按 `ClientServiceConfig.BackendMode` 二选一构建 18 个服务；`LocalServiceModule` / `GoUnaryServiceModule` 产出的 `IClientServices` 接口完全一致，两种模式都会执行 `AuthSessionCoordinator.EnsureCreated()`、`ActiveRunLifecycleCoordinator.EnsureCreated()`、`GameplayRunGatewayRegistry.Install(gameplay)`。→ 玩法/UI 不读 BackendMode，切模式不改玩法。
- **Local 实现特性**：全部基于 `PlayerPrefs` 本地模拟（LocalAuthGateway 用 device_id SHA256 生成 GUID playerId；LocalPlayerEnergyGateway 上限 30、3 分钟恢复、每日广告/分享次数；LocalPlayerGoldGateway 胜 20/负 10/早退 5、广告翻倍）。`LocalServerFeatureGateway` 同时充当 CloudSave/Push/Social/Snapshot，返回写死的假数据（好友列表恒空）。
- **Mock 化**：Local 走 `MockRewardedAdService` / `MockShareService`（不调真实 SDK，点了立刻成功）；GoUnary 走 `ClientReportedRewardedAdService` / `ClientReportedShareService`。
- **副作用三条**：① 切 Local 等于新号（playerId 生成方式不同，进度不继承，旧数据在另一套 PlayerPrefs key 下）；② 广告/分享变 mock，测不到真实回调；③ `requireAuthoritativeRunContract` 只被 `GoUnaryGameplayRunGateway` 读取，Local 路径完全不做快照摘要校验 → 之前的服务端 409（Settlement conflicts with run state）在 Local 下永不复现，只能在 GoUnary 验证。
- **不可用于发布**：`Assets/Editor/ClientServiceCompositionValidation.cs:15` 硬断言 `config.BackendMode == BackendMode.Local`（"Development backend must remain Local"）→ Local 是开发态；发布包必须 GoUnary + 正式 HTTPS。
- **⚠️ 2026-09-10 16:31 发现配置处于更坏的中间态**：`ClientServiceConfig.asset` 已变成 `backendMode: 1` + `apiBaseUrl:` 空。`GoUnaryServiceModule.Validate`（第 64 行）会因此抛 `InvalidOperationException("Go backend mode requires an API base URL.")`，异常发生在 `BeforeSceneLoad`，导致 `current` 保持 null，后续任何 `ClientCompositionRoot.Current` 访问都抛 "Client services have not been initialized."。这比原来的"连不上"更严重（启动期即异常），疑似即截图中的 Main 初始化报错。**必须二选一收敛：补回 apiBaseUrl，或把 backendMode 改 0。**

## 方案 B（真机联调 GoUnary）具体实现步骤 → `Docs/真机联调GoUnary后端配置方案.md`
- **配置现状已收敛**：`ClientServiceConfig.asset` 现为 `backendMode: 1` + `apiBaseUrl: http://192.168.31.221:8081`（URL 已补回，非空），`enableNetworkLogging: 0`。
- **关键新事实（构建产物实测）**：`targetSdk=35`、`minSdk=24`、ARM64、IL2CPP、包名 `com.drakeforge.mergedefense`；`Assets/Plugins/Android/` 下**没有**自定义主 manifest，合并后 manifest 里**无任何 cleartext 配置** → Android 9+ 默认 `cleartextTrafficPermitted=false`，明文 HTTP 必被拦。这解释了「Editor 能通、真机卡登录」。

- **三条子路径**：B-ADB（`adb reverse tcp:8081 tcp:8081` + `apiBaseUrl=http://127.0.0.1:8081`，变量最少、绕开防火墙，推荐先试）＞ B-LAN（同 Wi-Fi + 防火墙放行 + 服务须监听 `0.0.0.0`）＞ B-TUNNEL（HTTPS 隧道，可跳过明文放行）。
- **可客观验收的点**：构建后查 `Library/Bee/Android/Prj/IL2CPP/Gradle/launcher/build/intermediates/merged_manifest/debug/AndroidManifest.xml`，`<application>` 上应出现 `android:usesCleartextTraffic="true"`。
- **配置资产约束**：`apiBaseUrl` 必须绝对 HTTP(S) URL（`UnityWebRequestUnaryTransport` 构造校验 cs:37-48），末尾斜杠自动裁；空值会使 `GoUnaryServiceModule.Validate`（cs:64）在 `BeforeSceneLoad` 抛异常导致整个服务层构建失败。改的是 `Resources/` 下资产 → **必须重新构建 APK**。
- **构建入口**：`DragonBoundAndroidBuild.BuildApk()`（cs:320）**没有 MenuItem**，需 `-executeMethod DragonBound.Editor.DragonBoundAndroidBuild.BuildApk`；方法内 `BuildOptions.None`（非 Development Build）。
- **收尾必做**：删自定义 manifest + 取消 Custom Main Manifest 勾选 + 撤防火墙规则 + `enableNetworkLogging` 归 0 + 换 HTTPS 域名；建议在 `BuildApk()` 开头加断言禁止非开发包带 `http://`/`192.168.`/`127.0.0.1`。
- **联调期预期"失败"**：菜单 `DragonBound/Validation/Validate Client Services` 在非 Local 下必然报 "Development backend must remain Local."（`ClientServiceCompositionValidation.cs:15`），属预期。

## Unity 弹「No Android devices connected」根因（2026-09-10 16:50，现场实测）
- **根因**：设备**已插着**，但 adb 状态为 `unauthorized`，Unity 设备扫描只统计 `state=device` 的设备 → 扫描为空 → 弹框。**不是 USB 驱动 / 线材 / SDK 路径问题**。
- **实测证据**：Unity 自带 adb（`D:/2022.3.62f3c1/Editor/Data/PlaybackEngines/AndroidPlayer/SDK/platform-tools/adb.exe`）`devices -l` 输出 `9B051FFAZ00F5M  unauthorized transport_id:1`；`adb -s 9B051FFAZ00F5M get-state` 报 `error: device unauthorized.`。
- **环境事实（本机）**：Unity **2022.3.62f3c1（中国版）** 装在 `D:/2022.3.62f3c1/`；AndroidPlayer 模块已装；`adb` **不在 PATH**、`ANDROID_HOME`/`ANDROID_SDK_ROOT` 均空 → 一律用 Unity 自带 adb 全路径。ADB 密钥 `C:/Users/Administrator/.android/adbkey`（2026-06-17 生成）。
- **修复**：解锁手机 → 勾「一律允许」点「允许 USB 调试」；若无弹框：开发者选项「撤销 USB 调试授权」+ 重插；仍不行则 `kill-server` 后删 `~/.android/adbkey{,.pub}` 重新触发握手。`adb devices` 显示 `device` 后回 Unity 点 Retry。
- **排查命令备查**：Unity 自带 adb 全路径 + `devices -l` / `get-state`；Bash 里不要内联调用 PowerShell（被安全策略拦截，含 "PowerShell" 字样的 echo/heredoc 也会被拦），改用 PowerShell 工具或 Edit 工具写文件。

## 真机 Build and Run 后点击「游客登录」进不去 Main 的复核（2026-09-10 16:58）
- **直接原因**：`ClientServiceConfig.asset` 当前 `backendMode: 1`（GoUnary）+ `apiBaseUrl: http://192.168.31.221:8081`，但登录请求无法到达任何可用后端。
- **三个独立阻断点同时存在**：
  1. **后端未启动**：PC 上 `netstat -ano | findstr :8081` 无监听；即使网络可达也没服务。
  2. **IP 已过期**：本机当前局域网 IP 实测为 `192.168.31.34`，配置里的 `192.168.31.221` 已失效（B-LAN 走不通）。
  3. **Android 明文 HTTP 被禁**：`targetSdk=35`，合并后的 launcher manifest 无 `android:usesCleartextTraffic="true"`，`http://` 请求直接失败。
- **现场网络状态**：手机屏幕状态栏显示 **5G 图标、无 Wi-Fi 图标** → 手机当前用移动数据，未与 PC 同 Wi-Fi，B-LAN 方案**此时完全不可行**。
- **代码路径确认**：`LoginController.OnGuestLoginClicked` → `GoAuthGateway.GuestLoginAsync` → HTTP POST `/v1/auth/guest` → `UnityWebRequestUnaryTransport` 失败时状态码 0 → `NETWORK_ERROR` → 被包装为 `AuthException` → 界面显示 `"Unable to reach the game server."`。没有崩溃/ANR，登录按钮还在。
- **日志排查难点**：`enableNetworkLogging: 0` 导致 Unity 侧不输出 `[API] ...`，logcat 中几乎看不到 Unity 标签日志；需要先把 `enableNetworkLogging` 改 1 才能看到请求/响应。
- **结论**：这是「后端没起 + 地址错误 + Android 禁明文 HTTP + 手机没连 Wi-Fi」四重复合问题，不是登录逻辑或 UI 的 bug。**最快打通路径是 B-ADB**：起后端（监听 127.0.0.1:8081 即可）+ `adb reverse tcp:8081 tcp:8081` + `apiBaseUrl: http://127.0.0.1:8081` + 自定义 manifest 开 `usesCleartextTraffic` + 重构建。


## 真机登录数据清理与重新登录方案（2026-09-10 17:20）
- **输出文档**：`Docs/真机登录数据清理与重新登录指南.md`（清理范围 + 三种方案 + 清完后必做的两件事 + 验收清单 + 误区表）。
- **关键实况（2026-09-10 17:20 实测）**：
  1. **8081 LISTENING 是 `python.exe`（PID 39740）**，不是真 GoUnary 后端——是上次 AI 调试开的 Python `http.server` 占位，**不会**实现 `/v1/auth/guest`，客户端会因 `access_token`/`refresh_token` 为空抛 `AuthException("INVALID_RESPONSE", "Authentication response is incomplete.")`。
  2. **`verge-mihomo.exe`（PID 15984）** 正在连 `192.168.31.221:8081`（ESTABLISHED）——Mihomo 代理可能劫持 Unity 出站；登录前需临时关。
  3. **设备号变了**：从 `9B051FFAZ00F5M` 变为 `3B15AF0102T00000`（PLJ110，state=device，已授权）。
  4. PC IP 仍为 `192.168.31.34`，配置里 `.221` 仍失效。
- **真实清理范围**：
  - 必清：`/data/data/com.drakeforge.mergedefense/` 下 `shared_prefs/` + `files/` + `cache/`（一条 `adb shell pm clear com.drakeforge.mergedefense`）。
  - PlayerPrefs 关键 key：`dragonbound.auth.session.v1`（AuthSession，`PersistentAuthSessionStore.cs:11`）、`dragonbound.guest.device-id`（`GuestIdentityService.cs:11`）。
  - **结论**：因为登录从未真正成功（一直在 `NETWORK_ERROR` / `INVALID_RESPONSE`），`AuthSession` 大概率**从未写入**；`device-id` 可能写过一次。清客户端的意义在于"从已知干净起点开始 + 强制重新生成 device-id = 强制换号"。
- **核心告诫（必须传达给用户）**：**清完客户端不会让登录成功**——必须先打通链路：杀 python 占位 → 关 Mihomo → 起真 Go 后端（监听 `0.0.0.0:8081`）→ `adb reverse tcp:8081 tcp:8081` → 改 `apiBaseUrl: http://127.0.0.1:8081` + 开明文 manifest + 重构 APK + 装机。
- **推荐方案**：adb pm clear（一行搞定，可重复，不动 APK）。方案 B（系统设置）和 C（卸载重装）作为备选。
- **误区别再踩**：清完就能登录（错）/ Editor 通就等于真机通（错）/ Python 占位能测（错）/ Resources 改完热重启生效（错，必须重构）/ `adb reverse` 一次管终身（错）。
