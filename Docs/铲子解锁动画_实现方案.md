# 铲子解锁格子动画 实现方案

> 参考：《赵云与阿斗》中铲子拖到锁定地块后，铲子原地左右晃动"挖"几下，随后地块从锁定贴图"擦除式"过渡到解锁贴图。
> 本方案仅设计，未落地。所有代码路径以 2026-09-22 的 `codex/ui-v1-v2-isolation` 分支现状为准。

## 一、现状与可挂钩点（已核实）

| 环节 | 现状 | 挂钩点 |
|---|---|---|
| 解锁成功 | `ShovelUnlockService.TryUnlockCell`（`Runtime/Recruitment/ShovelUnlockService.cs:91`） | 已有 `ShovelUsed(GridPosition)` 事件，**点选/拖拽/AI 三条路径统一经过**，是挖掘动画的完美触发器 |
| 格子视觉切换 | `BoardGrid.TryUnlock` 发 `GridMutationKind.CellUnlocked` → `GreyboxBoardView.HandleBoardChanged`（:1969）→ `RefreshCellStates`（:2251）→ `GridCellView.ApplyDevelopmentVisual` **瞬时换 sprite**（`GameUI/Lock` → `GameUI/UnLock`） | 擦除过渡的切入点：`HandleBoardChanged` 目前无视 mutation 内容全量刷新，需改为按 `Kind == CellUnlocked` 单格路由 |
| 拖拽中反馈 | `UpdateShovelDragPreview`（:2364）已画箭头 + 目标格高亮（`boardSelectPreview`） | 悬停预抖动画可加在此处（可选阶段二） |
| 动画先例 | 全项目**无 DOTween**，统一手写协程 + `Time.unscaledDeltaTime` + smoothstep（`AnimateSynthesisComponentFade` :1617、`AnimateDeploymentFlight` :1131） | 新动画沿用同一风格，不引第三方库 |
| 幽灵节点 | `DraggableUnitView.CreateDragGhost(parent)` + `heroEffectLayer`（:43）是现成的"临时视觉挂层" | 挖掘铲子 ghost 挂 `heroEffectLayer`（fallback `unitLayer`），与合成 ghost 同款模式，不会被 `RefreshUnits` 销毁 |
| 变体资源 | 铲子 `ComponentUI/shovel`、锁定/解锁 `GameUI/Lock|UnLock` 均走 `UiAssets.Load` | 新增美术资源需同时进 V1/V2 注册表；MVP 复用现有 sprite 可零新资源 |

## 二、总体时序（单次解锁 ≈ 0.85s）

```
松手/点击锁定格 (TryUnlockCell 成功)
 ├─ t=0.00s  挖掘动画开始：铲子 ghost 在格子中心，3 次左右晃动±22°，每晃一下向下"啄"一次 + squash
 ├─ t=0.35s  擦除动画开始（与第 2~3 次晃动重叠）：锁定贴图被斜向擦除，露出下方解锁贴图
 ├─ t=0.55s  挖掘动画结束，铲子 ghost 淡出
 └─ t=0.75s  擦除完成，格子残留 0.1s 白色高亮闪 → 恢复正常
```

格子数据状态在 `TryUnlock` 时**立即**变为 Battle（游戏逻辑不等动画），动画纯视觉延迟——保证不阻塞部署等后续操作。

## 三、Effect A：铲子挖掘晃动动画

### 新组件 `ShovelDigEffectView`（`Runtime/Presentation/`，新文件）

自包含 MonoBehaviour，运行时动态构建，无需场景预制体：

```csharp
public sealed class ShovelDigEffectView : MonoBehaviour
{
    // Play(parent, cellRect, shovelSprite) 由 GreyboxBoardView 调用
    // 内部：Image(shovel) + 协程，结束后自毁 Destroy(gameObject, ...)
}
```

**动画细节**（对标《赵云与阿斗》的挖掘手感）：

1. **结构**：根节点 RectTransform 挂到 `heroEffectLayer ?? unitLayer`，position 对齐目标格 `ContentAnchor`；子节点 `ShovelPivot` 的 pivot 设 `(0.5, 0.08)`（**铲柄底端**为旋转轴，晃动才像"握着铲子挖"）；ShovelPivot 下放 Image 用 `UiAssets.Load<Sprite>("ComponentUI/shovel")`。
2. **晃动**：总时长 0.55s，3 个周期（周期 ≈ 0.183s）：
   - 每周期旋转 `rotation = sin(phase) * 22°`，左右各一次；
   - 同步每周期向目标格中心方向位移 6~10px 的"下啄"，即 `anchoredPosition.y` 下压再弹回；
   - 下啄瞬间 scale 短促压扁到 `(1.08, 0.92)` 制造击打感（squash & stretch）。
   - 缓动沿用项目惯例：`eased = p*p*(3-2p)` smoothstep，`Time.unscaledDeltaTime` 驱动（暂停菜单下不冻结视觉反馈，与合成 ghost 一致）。
3. **收尾**：第 3 次晃动后 0.15s 内 alpha 1→0（`CanvasGroup`），自毁。
4. **调度**：在 `GreyboxBoardView` 订阅已绑定的 `shovelUnlockService.ShovelUsed += HandleShovelUsed`（当前未订阅，需在 `BindShovelUnlockService` :533 增删对称加减）。Handler 里 `cells.TryGetValue(position, out cell)` 拿 ContentAnchor → 播放。**AI 侧自动免费获得**（`AiBoardView` 走同一份代码、绑的是 `AiShovelUnlocks`）；若不想要 AI 侧动画，加一个 `[SerializeField] bool playUnlockEffects` 开关即可。
5. **防重入**：同格连续解锁（理论上单格只能一次，但 Boss 锁定格可循环锁/解锁）时，若该格已在播放，直接 `StopAllCoroutines` 重启。

### 可选增强（阶段二，本方案不强制）

- **悬停预抖**：`UpdateShovelDragPreview` 命中有效锁定格时，对 `boardSelectPreview` 或格子本身加 ±3°/±2px 高频微抖，暗示"可挖"。实现为同一组件的 `PlayHoverShake` 轻量模式；拖走/取消时停。
- **挖土粒子**：项目已内置 Coffee.UIParticle 包，可挂一个 UIParticle 播尘土粒子；需要新粒子贴图则要进 V1/V2 双注册表（见第五节资源清单）。

## 四、Effect B：锁定 → 解锁擦除过渡

### 方案 B1（推荐）：RectMask2D 双层擦除，零新 shader

**原理**：格子底层立即换成解锁贴图（`ApplyDevelopmentVisual` 正常执行），上层盖一张**旧锁定贴图的副本**，用一个逐渐收缩的 `RectMask2D` 裁剪它——锁定贴图被斜向"擦掉"，露出下面的解锁贴图。

**实现要点**：

1. 新组件 `CellUnlockWipeView`（`Runtime/Presentation/`，新文件），由 `GridCellView` 或 `GreyboxBoardView` 在收到 `CellUnlocked` 时挂到目标格子上：
   ```
   GridCellView
     └─ UnlockWipe_Root (RectTransform, 铺满格子)
         ├─ RectMask2D                       ← 裁剪矩形从满格斜向收缩到 0
         │   └─ LockedSpriteCopy (Image, GameUI/Lock)
         └─ WipeEdge (Image, 细条, alpha 渐变) ← 擦除边缘的白色高亮线（可选）
   ```
2. **裁剪动画**：`RectMask2D.rectTransform` 的 `anchorMin` 从 `(0,0)` 渐变到 `(1,1)`（等效可视区域从满格收缩为对角点），时长 0.4s，方向为右上→左下（或与拖拽来源方向一致，见下）。**注意项目已有踩坑记录**（`DragArrowPreviewView.cs:113`）：RectMask2D 裁剪矩形参与旋转会退化——本节点**全程零旋转**，父链只有格子的 RectTransform，安全。
3. **擦除方向跟随铲子来源（加分项）**：`HandleShovelUsed` 时知道铲子来源格（bench 或 granted），取 `来源格中心 → 目标格中心` 的方向，把 wipe 起始角设为该方向的斜角；实现成本 ~15 行，手感提升明显。MVP 可固定为左上→右下。
4. **边缘高亮**：`WipeEdge` 为 8~10px 宽的白色半透明 Image，跟随裁剪边移动并渐隐，模拟"橡皮擦过去"的亮边。零新贴图（纯色 Image + CanvasGroup）。
5. **清理**：协程结束 `Destroy(wipeRoot)`；格子若有 `CanvasGroup` 不受影响。`RefreshCellStates` 的全量刷新不会碰到 wipe 子树（它只改 `ApplyRuntimeState` 的目标 Image）。

### 方案 B2（备选）：自写 UI wipe shader

自定义 UI shader（`_Progress` + 噪声/软边做 dissolve 式擦除），视觉上限更高（溶解颗粒感），但需要：
- 新 shader 资产 + `Material` 实例化（UI shader 需兼容 Canvas 渲染队列，`[HideInInspector] _MainTex` 需对齐 UI 的顶点色/加色逻辑）；
- 打包变体收集（ShaderVariantCollection）与 V1/V2 无关但增加维护面。

**建议先落地 B1**（纯 UGUI、零依赖、零新 shader），验证手感后若美术要求"溶解颗粒感"再升级 B2，两者接口（`CellUnlockWipeView.Play(...)`）可保持不变，只换内部实现。

## 六、集成细节与已知坑

1. **`HandleBoardChanged` 不能再无脑全量刷新**：当前实现任何 mutation（含 `CellUnlocked`、Boss 锁格 `CellLocked`）都触发 `RefreshCellStates`，会把锁定贴图**立即**换成解锁贴图，视觉上"闪变"。必须先分流：`CellUnlocked` 时**先不换 sprite**，由 wipe 组件控制新旧贴图的呈现次序（解锁贴图作为 wipe 组件底图，锁定贴图作为被擦层；结束后调 `ApplyRuntimeState` 收尾归位）。**注意**：`RefreshCellStates` 还会被 :593（绑定/重布局）调用，需保证 wipe 结束后状态与 `RefreshCellStates` 幂等一致。
2. **ghost 生命周期**：挖掘铲子 ghost 必须挂 `heroEffectLayer`（合成 ghost 同款），不能挂 bench 卡片本身——`HandleShovelStateChanged`（:1559）在解锁成功后会 `RefreshUnits()` 重建 bench 视图，挂在卡上的东西会被一起销毁。
3. **`ShovelUsed` vs `StateChanged` 时序**：`TryUnlockCell` 内先 `board.TryUnlock`（发 `CellUnlocked`）再发 `ShovelUsed`/`StateChanged`——即擦除的触发（mutation 事件）先于挖掘动画的触发（ShovelUsed 事件）。协调方式：擦除组件 `Play` 时带 `delay = 0.35s` 参数内部等待，不需要外部队列；两个动画彼此独立、靠时间轴重叠。
4. **逻辑与视觉解耦**：格子数据在 `TryUnlock` 瞬间已变 Battle，动画期间玩家可立即拖兵进格——**建议不阻断**（保持手感；部署协程 `AnimateDeploymentFlight` 的层级在 wipe 之上，视觉可共存）。
5. **多格并发**：Boss 战连挖多格 / AI 同时解锁时每个格子独立 wipe，互不干扰；协程各自挂在各自 wipe 组件上，无共享状态。
6. **AI 侧效果**：`AiBoardView` 绑定 `AiShovelUnlocks`，同样会播动画（对称、信息透明）。若嫌吵，用开关关闭。
7. **V1/V2**：全部代码在共享 Runtime 程序集，一次实现两版本同时生效；唯一差异点是三个 sprite（shovel / Lock / UnLock）各自走注册表，天然支持双版本不同美术。
8. **性能**：单次解锁临时创建 2 个小 GameObject（dig ghost + wipe root），用完即毁，频率极低（受铲子产出率限制），无对象池必要；如后续要池化，参考 `synthesisComponentGhosts` 的 List 管理模式。

## 七、实施顺序（建议 PR 拆分）

1. **PR-1**：`HandleBoardChanged` 分流 + `CellUnlockWipeView`（B1 擦除）——先拿到"擦除"这个核心反馈；
