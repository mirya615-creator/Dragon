Date: 2026-08-17
Scope: isolated analytics schema, local sinks, deterministic recorder rules and regression documentation. No analytics SDK, network transport, battle rule, numerical balance, scene or prefab was changed.

- Unity Targeted attempt: blocked before project initialization. The empty batch process started by this task was terminated after observation to release the shared workspace.
- Fast EditMode and PlayMode were not started because they would encounter the same launcher blockage and add concurrent Unity contention. No pass count is claimed for this task.

Required follow-up once the local Unity batch launcher is healthy: run the Targeted command in `QARegressionMatrixV1.md`, then Fast EditMode; PlayMode is required when a future gameplay/bootstrap adapter wires the schema.

## Integration status and risk

- The local event model is ready; no gameplay event is wired in this phase by design.
- Event IDs are generated by the future bootstrap/adapter. The recorder verifies them but intentionally does not invent random IDs, preserving deterministic test control.
- JSONL writes are local QA artifacts. The recorder's in-process dedupe must be backed by service-side dedupe if telemetry upload/retry spans process restarts.
- W6 currently provides a typed `SoulChainController.CastEvent` and player rune-reward event. Several required events still have only logs or private lifecycle points; the hook register in `QARegressionMatrixV1.md` names the safe adapter locations.

## Product Rule Drift / Code Migration Gap

Confirmed product rule as of 2026-08-17: the Item System permanently unlocks after an account has **normally completed five Runs**. Both victories and defeats count; abnormal exits do not. This is account progress, not DayKey state. Daily Item inventory remains a separate DayKey-scoped asset and still clears on the next server DayKey.

This QA/Analytics V1 contract deliberately contains no superseded unlock condition as an event field, rule or acceptance criterion. The latest V11 product authority and corrected configuration baseline are the source of truth for the five-completed-run rule. In this worktree snapshot, `Assets/DragonBound/Runtime/Items/ItemProfile.cs` and its related Item Foundation tests still implement a superseded unlock condition; that is the code migration gap. `ItemSystemV1FoundationVerified.md` is historical test evidence, not current acceptance criteria. Updating Item profile code/tests belongs to the Item/profile owner and was not changed in this isolated QA task.
