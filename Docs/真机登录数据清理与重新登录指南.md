# 真机登录数据清理与重新登录指南

> 目标：把刚才手机登录尝试在客户端留下的所有痕迹清干净，从一个**明确已知起点**重新走登录流程。
> 关键提醒：**清理客户端数据本身不会让登录成功**。本指南最后两节是"清完后必须做的两件事"，必须按顺序做完才能真正登录进 Main。

---

## 0. 实况速读（2026-09-10 17:20 现场实测）

| 项 | 值 | 含义 |
|---|---|---|
| PC 局域网 IP | `192.168.31.34` | 配置里 `192.168.31.221` 已失效 |
| 8081 LISTENING | **`python.exe`（PID 39740）** | **不是 GoUnary 后端**——是上次调试用的 Python `http.server` 占位服务。它能响应 `GET /`（返回 200 + 目录索引），但**不会**实现 `/v1/auth/guest`，客户端会因 `access_token`/`refresh_token` 为空抛 `AuthException("INVALID_RESPONSE", "Authentication response is incomplete.")` |
| ESTABLISHED → `.221:8081` | **`verge-mihomo.exe`（PID 15984）** | PC 上的代理软件正连向失效地址。**Unity 出站请求可能被它劫持**（mihomo 会接管系统代理或 TUN 模式流量），清完登录前先确认 |
| ADB 设备 | `3B15AF0102T00000`（PLJ110，state=`device`） | 已授权，`adb shell pm clear ...` 可直接发 |
| 当前配置 | `backendMode: 1` + `apiBaseUrl: http://192.168.31.221:8081` | `.221` 失效 → 即使关掉代理、起真后端，B-LAN 也连不通 |
| 客户端登录日志 | `enableNetworkLogging: 0` | logcat 里看不到 `[API]` 行；判断"卡在哪一步"只能靠现象 |

### "刚刚登录后的所有数据"实际是什么？

登录失败链路（参见 `Assets/Scripts/Auth/UI/LoginController.cs:198-230` + `Assets/Scripts/Auth/Infrastructure/GoAuthGateway.cs:23-40`）：

| 失败位置 | 写入客户端的数据 |
|---|---|
| `GuestLoginRequest` 构造（`GuestIdentityService.CreateRequest`） | **首次**会写 `dragonbound.guest.device-id`（之后一直复用） |
| `authGateway.GuestLoginAsync` 失败抛 `AuthException` | **不写** `AuthSession` |
| `authSessionStore.Set(session)` **只在成功后调用** | **不写** `dragonbound.auth.session.v1` |
| `LoadMainScene()` 成功才会跳 | **不切场景** |

→ 真实情况：**`AuthSession` 大概率从未写过**；`device-id` 可能写过也可能没写过（取决于是否走到 `CreateRequest`）；其他 PlayerPrefs（头像、能量、金币、对局快照、签到）理论上也都没写，因为 `LoadMainScene()` 没成功过。

但**完整清理一遍没坏处**：① 把"登录状态残留"彻底归零；② 强制重新生成 `device-id`（相当于换号）；③ 排除"上次半成功半失败"的边角情形。

## 1. 清理范围分类（清什么 / 不清什么）

### 1.1 必须清：客户端持久化数据

| 位置 | Android 路径 | 内容 | 来源 |
|---|---|---|---|
| PlayerPrefs | `/data/data/com.drakeforge.mergedefense/shared_prefs/com.drakeforge.mergedefense.xml`（在 Unity Player 里也即 `PlayerPrefs` 文件） | `dragonbound.auth.session.v1`（AuthSession）、`dragonbound.guest.device-id`（设备级游客 ID）、`dragonbound.rank.season.v1`（赛季档案）、`dragonbound.signin.*`、`dragonbound.pending-ad-event`、`dragonbound.pending-share-event`、其他各子系统缓存 | `Assets/Scripts/Auth/Session/PersistentAuthSessionStore.cs:11`、`Assets/Scripts/Auth/Infrastructure/GuestIdentityService.cs:11`，以及 `Grep` 命中的所有脚本 |
| 持久化文件 | `/data/data/com.drakeforge.mergedefense/files/` | 各子系统 `Application.persistentDataPath` 写入的 JSON / 二进制 | 多个 |
| 应用缓存 | `/data/data/com.drakeforge.mergedefense/cache/` | OkHttp / UnityWebRequest 缓存、未完成的网络栈缓冲 | 系统 + Unity |

### 1.2 不必清：环境与配置

- ❌ **不要动** USB 调试授权（重新授权更麻烦）
- ❌ **不要动** 开发者选项、`adbkey`
- ❌ **不要动** 手机 Wi-Fi、APN、5G 设置
- ❌ **不要改** PC 上 `ClientServiceConfig.asset`（除非打算顺便切 Local 试）

### 1.3 可选清：服务端游客账号

`device-id` 清掉后，**客户端会生成新 device-id**；服务端若按 `device-id` 索引游客账号，新 device-id = **全新游客**（旧账号作废）。但若服务端有独立的 `player_id` 持久化，需要服务端手动删号才能"完全换号"。

> 本工作区无服务端源码，无法直接执行。若需"换号"且旧号有需要清的资源，**告诉服务端同事让他在对应 DB 表（按 device-id 或 player_id）删行**。

### 1.4 必查：PC 上有"假后端"在跑

`python.exe`（PID 39740）正在监听 `0.0.0.0:8081`，**这是上次联调开的 Python 占位服务**，**不会**实现 `/v1/auth/guest`。如果你不清掉它就起真 Go 后端，会**端口冲突**（Go 后端起不来）。

## 2. 三种清理方案对比

| 方案 | 触发 | 清干净程度 | 推荐场景 |
|---|---|---|---|
| **A. `adb pm clear`**（推荐） | PC 上发一条 adb 命令 | 清掉 shared_prefs + files + cache，**不动 APK/资源** | 日常调试（最常用） |
| **B. 手机系统设置** | 设置 → 应用 → DragonBound → 存储 → 清除数据 | 同 A | 不想接 USB |
| **C. 卸载重装** | `adb uninstall` 或手机长按图标卸载 | 同 A + 卸载（重新装后是全新） | 想验"完全干净 + 新装包" |

**选 A 即可**——一行搞定、可重复、不动 APK。

## 3. 具体步骤（推荐：方案 A）

> 前置：手机 USB 连上 PC；PC 上 adb 已识别（实测 `3B15AF0102T00000 device`）；包名固定为 `com.drakeforge.mergedefense`。

### 3.1 清理客户端（核心一条命令）

```bash
# 全程用 Unity 自带 adb（不在 PATH）：
ADB='/d/2022.3.62f3c1/Editor/Data/PlaybackEngines/AndroidPlayer/SDK/platform-tools/adb.exe'

# 1) 停掉 App（防清理过程中在写）
$ADB shell am force-stop com.drakeforge.mergedefense

# 2) 清除所有 App 数据（shared_prefs + files + cache + databases）
$ADB shell pm clear com.drakeforge.mergedefense

# 3) 验证：清完后 PlayerPrefs key 应该都没了
$ADB shell run-as com.drakeforge.mergedefense ls -la shared_prefs/ 2>/dev/null
# 期望：目录不存在 / "No such file or directory" / 空
```

> `pm clear` 会同时清掉 shared_prefs / files / cache / databases / external storage（仅 App 私有部分）。**不会**清掉 `obb/` 下的扩展资源。
> `run-as` 仅 debug 包可用；本项目是 `BuildOptions.None` 但内部调试清单可能允许；若失败用 `adb shell ls /data/data/com.drakeforge.mergedefense/` 直接看（需要 root 或 run-as）。

### 3.2 顺手：停掉 PC 上的 Python 假后端

```bash
# 干掉上次 AI 起的 Python 占位服务（确认是 39740）
taskkill /PID 39740 /F

# 验证 8081 已无监听
netstat -ano | grep -a 8081
# 期望：空（除非你另有真 Go 后端要起）
```

### 3.3 顺手：关掉 Mihomo 代理对 Unity 出站的影响

```bash
# 看进程在不在
tasklist /FI "IMAGENAME eq verge-mihomo.exe" /FO LIST

# 临时停（关掉整个代理软件）
taskkill /IM verge-mihomo.exe /F

# 验证：路由表应回到系统默认
netsh interface ip show dns | head -10
```

> Mihomo/TUN 模式会**接管所有出站流量**，Unity 的 `UnityWebRequest` 也会被代理。临时关掉是排除"网络栈被代理劫持"的最快路径。验证登录链路通了之后，再决定要不要让代理放行 `192.168.x.x` / `127.0.0.1`。

## 4. 清完后必须做的两件事（否则登录仍会失败）

**清理本身不会让登录成功**。登录失败的根因是后端链路不通，按本工作区已有文档 `Docs/真机联调GoUnary后端配置方案.md` 的"四重复合问题"处理：

### 4.1 决策：选 GoUnary 真后端，还是临时切 Local？

| 选项 | 何时选 | 怎么做 |
|---|---|---|
| **GoUnary 真后端**（推荐：贴合正式形态） | 服务端同事能起来 Go 后端；想验证完整链路 | 让他在服务端机器跑 `go run ./cmd/server -listen 0.0.0.0:8081`，然后按 §4.2 验证 |
| **临时切 Local**（最快：完全离线） | 服务端今天没空；只想先把 UI 走通 | 把 `ClientServiceConfig.asset` 改 `backendMode: 0`，重构建一次（**Resources 下资产必须重构建**，热重启不生效） |

### 4.2 若是 GoUnary：按 B-ADB 或 B-LAN 打通路（详见真机联调方案 §1）

**最省事路径 B-ADB（推荐）**：

```bash
ADB='/d/2022.3.62f3c1/Editor/Data/PlaybackEngines/AndroidPlayer/SDK/platform-tools/adb.exe'

# a) 真后端确认在 0.0.0.0:8081 监听（不是你刚才 kill 的 python）
netstat -ano | grep -a 8081
# 期望：TCP  0.0.0.0:8081  LISTENING  <新PID>

# c) 反向端口映射
$ADB reverse tcp:8081 tcp:8081
$ADB reverse --list   # 期望 127.0.0.1:8081 tcp:8081 tcp:8081

# d) PC 浏览器实测（必须 200，不能 502/timeout）
curl -sS -m 3 -o /dev/null -w "HTTP %{http_code}\n" http://127.0.0.1:8081/v1/auth/guest
# 注：guest 端点要 POST + 合法 body 才返回 200；GET 会 404/405，看到 404/405 也算"链路通"，
#     看到 connection refused 才是真不通。
```

**改工程配置**（`Assets/Resources/Configuration/ClientServiceConfig.asset`）：
```yaml
backendMode: 1
apiBaseUrl: http://127.0.0.1:8081        # B-ADB 固定 127.0.0.1
enableNetworkLogging: 1                  # 联调期开，看 [API] 日志
```

**新建明文 manifest**：`Assets/Plugins/Android/AndroidManifest.xml`（参见真机联调方案 §3.1），并勾选 `Publishing Settings → Custom Main Manifest`。

**重新构建 APK**（详见真机联调方案 §5）：
```bash
# Unity GUI：File → Build Settings → Android → Build
# 或命令行：-executeMethod DragonBound.Editor.DragonBoundAndroidBuild.BuildApk
```

**安装**：
```bash
ADB='/d/2022.3.62f3c1/Editor/Data/PlaybackEngines/AndroidPlayer/SDK/platform-tools/adb.exe'
$ADB install -r "Builds/Android/DragonBound-Greybox.apk"
$ADB reverse --list   # 装机不影响，但重插过线要重跑
```

### 4.3 验证链路（不要靠猜，看 logcat）

```bash
ADB='/d/2022.3.62f3c1/Editor/Data/PlaybackEngines/AndroidPlayer/SDK/platform-tools/adb.exe'

# 清 logcat 缓冲
$ADB logcat -c

# 启动 App
$ADB shell am start -n com.drakeforge.mergedefense/com.unity3d.player.UnityPlayerActivity

# 看 Unity 日志（需要 enableNetworkLogging: 1）
$ADB logcat -s Unity:V | grep -iE "API |NETWORK_ERROR|Cleartext|Exception"
```

| 看到 | 含义 |
|---|---|
| `[API] POST /v1/auth/guest` 后接 `[API] 200 ...` | ✅ 链路打通，进游戏 |
| `[API] 0 POST ...` + 系统日志 `Cleartext HTTP traffic ... not permitted` | ❌ manifest 未生效，回到 §4.2 自定义 manifest |
| `[API] 0 POST ...`，无 Cleartext 字样 | ❌ 路由不通；查 `adb reverse --list` / 真后端监听 / Mihomo 是否关 |
| `INVALID_RESPONSE` / `Authentication response is incomplete.` | ❌ 后端是 Python 占位或响应缺字段，回到 §3.2 杀掉 python 让真 Go 后端起 |
| 启动期直接抛 `Client services have not been initialized.` | ❌ `apiBaseUrl` 为空或非法；检查配置是否已生效（**Resources 下资产必须重构建**） |

## 5. 重新登录验收（最小清单）

按顺序勾选：

- [ ] `adb shell pm clear com.drakeforge.mergedefense` 已执行
- [ ] `netstat -ano | grep 8081` 显示的是真 Go 后端（不是 python），监听 `0.0.0.0:8081`
- [ ] PC 浏览器 `curl http://127.0.0.1:8081/` 返回 200/405/404（不是 connection refused）
- [ ] `adb reverse --list` 输出含 `127.0.0.1:8081 tcp:8081 tcp:8081`
- [ ] `Assets/Resources/Configuration/ClientServiceConfig.asset` = `backendMode:1` + `apiBaseUrl:http://127.0.0.1:8081` + `enableNetworkLogging:1`
- [ ] `Assets/Plugins/Android/AndroidManifest.xml` 已建（明文放行）；`Player Settings → Custom Main Manifest` 已勾
- [ ] APK 已重新构建并 `adb install -r`
- [ ] Mihomo 代理已临时关掉（排除出站劫持）
- [ ] logcat 看到 `[API] POST /v1/auth/guest ... 200`，登录按钮触发后跳转 Main
- [ ] 进 Main 后 `adb logcat` 还能看到后续 API 调用（energy、signin、avatar 等）

## 7. 常见误区（清完后仍会失败的高频坑）

| 误区 | 现象 | 真相 |
|---|---|---|
| "我清完客户端就能登录了" | 清完依旧 NETWORK_ERROR | **必须**先打通后端 + 改 manifest + 重构 APK |
| "在 Editor 里能登录就等于真机能" | Editor 通、真机卡 | Editor 不受 Android `usesCleartextTraffic` 约束 |
| "Python 起个 server 占位就能测" | 客户端抛 `INVALID_RESPONSE` | `GoAuthGateway.ToSession` 校验 `access_token`/`refresh_token` 必须非空 |
| "Resources 下改完就行，不用重构建" | 改动无效 | **Resources 下资产打进 APK**，必须重构建 |
| "代理开着反正也能通" | Unity 出站请求被劫持到失效代理 | Mihomo/TUN 模式接管所有出站；先关代理验证 |
| "`adb reverse` 一次管终身" | 拔线 / 重启后失效 | **每次重插/重启 adb 都要重跑** |
| "后端跑在 `127.0.0.1:8081` 就能让手机连" | 手机连不上 | `127.0.0.1` 对手机是手机自己；要么走 `adb reverse`，要么服务端必须 `0.0.0.0` + 同网段直连 |
| "清掉设备 ID 就能换号" | 同 device-id 仍可能复用旧 player_id | 真正的"换号"需服务端按 device-id 或 player_id 删行 |
