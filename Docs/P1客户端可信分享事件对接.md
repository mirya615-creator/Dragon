# P1 客户端可信分享事件对接

## 范围

P1 暂不接入分享平台回调。玩家点击“签到分享加倍”或“体力分享”后，客户端直接向服务端声明分享成功，服务端按已有账户、每日次数和幂等规则结算奖励。

客户端不会上传奖励数量或修改本地权威余额。服务端仍负责发奖、限次和返回最新资源快照。

## 签到分享加倍

调用：`POST /v1/signin/claim`

请求示例：

```json
{
  "expected_day_key": "2026-09-03",
  "claim_mode": "share_double",
  "client_share_succeeded": true,
  "client_share_event_id": "signin.share.<32位稳定摘要>",
  "share_platform": "android"
}
```

- `client_share_event_id` 由 `player_id + "|" + expected_day_key` 生成稳定摘要；同一玩家同一天重复请求保持不变。
- 请求幂等键：`signin.claim:<day_key>:share_double`。
- 非分享普通签到仍发送 `claim_mode=standard`，分享成功字段为空或 `false`。

## 体力分享

客户端在本地立即判定分享步骤完成，然后顺序调用：

1. `POST /v1/share/create`
2. `POST /v1/share/claim`
3. `GET /v1/share/status`

创建请求：

```json
{
  "platform": "android",
  "placement_id": "energy_share",
  "client_share_succeeded": true,
  "client_share_event_id": "<32位客户端事件ID>"
}
```

领取请求：

```json
{
  "share_id": "<create返回值>",
  "share_token": "<create返回值，可为空>",
  "platform": "android",
  "placement_id": "energy_share",
  "client_share_succeeded": true,
  "client_share_event_id": "<与create相同>"
}
```

- 创建幂等键：`share.create:<client_share_event_id>`。
- 领取幂等键：`share.claim:<client_share_event_id>`。
- 网络结果不明确时复用事件 ID；P2 已将该待结算事件持久化，应用重启后仍不会生成新的领取事件。
- 平台枚举为 `android`、`ios`、`editor`。

## 服务端需配合

- 临时接受 `client_share_succeeded=true` 作为成功依据，不等待第三方平台回调。
- 以“玩家 + placement + client_share_event_id”去重，并让相同幂等键返回首次提交结果。
- 每日次数检查与发奖必须在同一原子事务内完成，不能因并发或重试重复发奖。
- 奖励数值、每日上限和账户资源快照均以服务端配置为准；忽略客户端代码中的展示值。
- `/v1/share/status` 的 `claimed_count` 表示已成功领取次数，`remaining` 表示剩余次数。
- `/v1/share/claim` 成功响应继续返回 `energy.current`、`energy.max`、`energy.next_recover_at`。

## 后续替换

接入正式分享 SDK/平台回调后，移除客户端可信字段作为结算依据；保留事件 ID 和幂等处理，将成功依据切换为服务端校验的平台凭证或回调记录。
